# 玩法设计

本文件定义课程 Demo 的玩法规则。4～8 人对局、大厅自动匹配，以及指定墙体、掩体、部分楼板破坏与局部坍塌已确认。具体地图布局、匹配参数、对局细则及平衡数值为首轮联调建议，需通过试玩调整。技术实现遵守[服务端设计](03-server.md)和[破坏系统设计](04-destruction.md)。

## 1. 核心体验

玩家通过移动、瞄准和射击与另一队交战。手雷除了造成伤害，还可以摧毁指定墙体、掩体或楼板，暴露敌人、打开侧翼路线或触发局部坍塌。破坏应改变战术选择，而不只是产生粒子效果。

首版重点展示三个场景：击毁掩体迫使对手转移；炸开指定墙面形成新路线；破坏局部支撑或楼板，使预先设计的建筑区域坍塌。保留不可破坏的边界和主要承重骨架，防止地图完全失去可玩性。

视觉采用立体纸模：场景、武器与碎块具有纸纹和折面，破坏后暴露纸芯层次与裁切边缘。纸模属于美术表达，武器伤害与破坏阈值仍按本文件及破坏系统配置；不因为视觉像纸板而自动改变物理或伤害规则。队伍标识、角色轮廓、可破坏区域与缺口边界应在纸色背景中清晰可辨。

## 2. 对局规则

| 项目    | 首版建议                                                    |
| ----- | ------------------------------------------------------- |
| 模式    | 两队团队竞技；自动分队，人数差不超过 1                                    |
| 人数    | 4～8 人为演示基线；联调允许两人分别处于不同队伍                               |
| 开始条件  | 当前匹配名单的玩家全部入场就绪且两队均有人，开始 5 秒倒计时；条件失效则停止倒计时，按入场失败流程处理    |
| 胜利条件  | 先获得 30 分，或 8 分钟结束时得分较高                                  |
| 计分    | 每次有效击杀敌方玩家加 1 分；自杀与环境死亡不加分                              |
| 平局    | 时间结束且同分，判为平局，不增加加时规则                                    |
| 结算    | 显示两队得分和个人击杀／死亡，15 秒后返回大厅；服务器清场并重置地图，玩家点击匹配再进入新局         |
| 加入与离开 | 仅入场等待阶段接纳本局已分配且资格有效的玩家；对局中可退出，人数失衡不强制换队；任一队无人则结束并标记对局中止 |

玩家流程：大厅 → 排队 → 分配成功 → 加载与入场等待 → 开局倒计时 → 对局中 → 结算／中止 → 返回大厅。服务器在结算后清场、重载地图并报告可用，随后才能承接新匹配。倒计时和比赛结束时间由服务器提供，客户端显示剩余时间，不独立决定结束。

### 大厅与匹配规则

- 首版建议单一团队竞技队列，按排队顺序凑齐配置人数；演示配置为 4～8 人中的一个目标人数，联调可单独配置为 2 人。名单人数与开局条件使用同一配置，不能因已有两人加载完成就提前开局。
- 等待时可以取消匹配；无可用战斗实例时继续排队并显示状态。匹配成功后由战斗服务器对分配名单自动均衡分队。
- 不在分配完成后临时补人：入场超时或开战前有人退出（包括倒计时期间），取消本次开局，将已入场玩家退回大厅，释放资格和实例预留；玩家可自行再次匹配。
- 取消与分配同时发生时，以服务端返回的当前状态为准；已分配玩家的退出按开局取消处理。具体幂等与超时契约见[服务端设计](03-server.md)。
- 首版不安排好友组队、段位或水平匹配；账号和跨局战绩是否必做仍待确认。临时玩家会话也必须支持可靠区分玩家和限制重复排队。

M1～M2 可使用固定地址直连与重置后循环开局完成联调；M3 起以上大厅流程为正式入口，最终验收包含结算后返回大厅及再次匹配。

## 3. 角色与操作

| 操作 | 默认按键／方式 |
| --- | --- |
| 移动、观察 | WASD、鼠标 |
| 跳跃、冲刺 | 空格、按住 Shift |
| 射击、瞄准 | 鼠标左键、按住右键 |
| 换弹、投掷手雷 | R、G |
| 菜单 | Esc；菜单不暂停联机世界 |

首版不包含滑铲、攀爬、趴伏和近战。冲刺与射击互斥，按下射击时结束冲刺；死亡或比赛未开始时禁止攻击。镜头后坐力和武器动画先保证清晰、稳定，不实现复杂配件与枪械改装。

## 4. 战斗数值与判定

| 项目 | 首轮调试值 |
| --- | --- |
| 生命值 | 100；首版不自动恢复，重生恢复满值 |
| 步枪 | 射线命中；单发伤害 25；射击间隔 0.1 秒；不区分头部倍率 |
| 弹药 | 弹匣 30，备用 90；换弹耗时 2 秒；无换弹期间射击 |
| 手雷 | 每次重生 1 枚；投出后 3 秒爆炸；伤害半径 350 cm |
| 爆炸伤害 | 中心最大 100，随距离线性衰减至边缘 0；由服务器按统一取整规则计算 |
| 友军伤害 | 关闭；自身手雷伤害开启 |
| 碎块伤害 | 首版关闭；少量关键大块可阻挡，但不实现砸伤规则 |

服务器检查角色状态、弹药、射速和合理瞄准方向后，执行射线或爆炸判定。客户端不能直接提交“命中了谁、造成多少伤害”。本地立即播放开火、后坐力和枪口效果，命中反馈由服务器确认。

步枪优先实现对玩家的伤害和表面命中效果。首版结构破坏由手雷触发，普通步枪不破坏墙体；可射穿／射碎的特殊材料留作扩展。手雷的角色伤害与结构应变使用独立参数，避免修改物理破坏阈值时同时改变战斗伤害。

爆炸的遮挡按爆炸生效时服务器的结构碰撞状态查询：先取得角色遮挡与伤害结果，再应用本次结构破坏。由本次爆炸刚打开的墙洞，不让同一次爆炸额外穿墙伤人。

## 5. 死亡与重生

生命值降至零后进入死亡状态，服务器停止该角色的攻击与移动能力，结算击杀归属。3 秒后重生，恢复生命、弹药和手雷数量。

地图提供预设出生点，优先选择远离敌方的己方可用点，不引入完整导航或动态生成算法。重生后有 1.5 秒保护，主动开火或投掷立即取消；保护状态应有明确视觉提示。所有预设出生点处于不可破坏的安全区域，避免地板被摧毁导致重复坠落。

## 6. 地图与破坏约束

- 一张小型地图，至少包含主交战路线和可通过破坏打开的侧翼路线。
- 可破坏构件采用统一材质或外观提示，让玩家能预判哪些区域可以破坏。
- 关键缺口必须同时改变画面、角色通行碰撞和子弹阻挡。
- 小碎屑不阻挡角色、不挡子弹、不造成伤害；玩家不能利用本地碎屑获得不同的战术结果。
- 普通扬尘仅作视觉反馈，不设计成战术烟雾；限制其持续时间和不透明程度。
- 每局地图从完整状态重新开始，不保存上一局废墟。

局部坍塌使用制作好的破碎层级、连接关系和固定区域，不承诺任意建筑形态的真实承重计算。若性能或联机质量不足，优先减少细碎屑和可交互残骸，保留关键缺口与路线变化。

## 7. 界面与验收场景

最小界面包含：大厅、匹配与取消、排队状态、加载与入场等待、队伍、准星、生命／弹药／手雷数量、双方比分、剩余时间、死亡倒计时、结算页、返回大厅和失败提示。

| 验收场景 | 预期结果 |
| --- | --- |
| 自动匹配与入场 | 玩家点击匹配后被分配到同一局并自动分队；名单未全部就绪时不提前开局 |
| 取消与失败 | 排队可取消；分配冲突、未到齐或实例不可用时结果明确，释放旧资格后可再次匹配 |
| 两队射击与换弹 | 命中、扣血、弹药和计分由服务器统一决定，无死亡后继续伤害 |
| 重生与保护 | 按规则重生；保护期不能受伤，主动攻击后取消保护 |
| 掩体与墙面破坏 | 至少两客户端认可同一缺口，均可通行且射击遮挡一致 |
| 局部坍塌 | 指定区域能够倒塌，出生区和地图边界仍可用 |
| 连续爆炸 | 不因碎屑差异产生卡人、单端掩体或客户端独有伤害 |
| 比赛结束与下一局 | 终止攻击、显示结果并返回大厅；服务器重置得分与破坏状态后可接纳下一次匹配 |
